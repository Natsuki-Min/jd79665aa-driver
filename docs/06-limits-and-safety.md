# 06 · 边界、失败方向与安全

这一章不是“免责声明”，而是把**已经撞过的墙**写清楚，免得下一个人从头再撞一遍。

## 1. 三条硬边界

1. **不要写面板 MTP/OTP。** 本包所有研究都是只读 MTP；没有 MTP 编程/擦除命令，也没有 OTP 写入。写坏的是面板，不是 Pico。
2. **研究固件只加载到 RAM。** 历史实验用 `picotool load -f -x` 把 ELF 放进 Pico RAM，断电即失；没有改 Pico Flash。基础驱动是普通 UF2，写到 Pico Flash 没问题，但它仍然不碰面板 MTP。
3. **结论只对这一块屏负责。** 换批次、换温度档、换 FPC、换供电，先重测。不要把 `profile-01` 当通用固件。

## 2. 还没解决的

| 问题 | 现在到哪 |
| --- | --- |
| 原厂完整波形复现 | MTP 表解出来了，但 535 B 没有整表回灌做 BUSY/VSL/光学复现 |
| MTP wrapper / 选表 | 22 B wrapper、profile 0/1 选择、温度语义都没解 |
| 绝对电压 | ADC 网络没有独立校准；文中电压都是标称反算 |
| H1 首状态 | 有“空前缀/不用 H1”的实用解，机制没完全解释 |
| 电平字节 bits 1:0 | 没看到新增平台，用途未知 |
| C/F 时长 bit 7 | 没找到保持功能，也没排除其他作用 |
| 六入口真实 bank | 写地址回绕已证，物理结构未证 |
| R83 窗口外 | 主要驱动范围有限制，但不保证零电场/长期无残留 |
| 快速视频画质 | 24 fps 级别跑过，但偏色、拖影、黑白终点没解决 |
| 长期电荷平衡/寿命 | 只有几轮、几十秒到几分钟的验证 |

## 3. 已经试过、别再重复的

这些是**负结果**。不是“理论上不可能”，是“在这块屏、这些条件下已经失败”。

| 方向 | 结果 |
| --- | --- |
| 靠继续加负剂量把黄擦回白 | 走过黑的像素回不到“没黑过”的淡黄；剂量 12→42 拍，R−B 先升后降，仍高于未黑参照 |
| 3 拍快路径 | 快（约 26 fps 级），但明显偏黄 |
| 6 拍中性白 | 白变灰，白 R−B 约 0，但亮度只有 131 左右 |
| 9 拍白 | 白最好（约 144.5），但只有约 11 fps |
| 简单线性 q 模型 | 被相机否决 |
| 纯负剂量 / 弱负单扫描累计等价长 AC | 被相机否决 |
| FAST + 交错 CLEAN 还白债务 | 被相机否决 |
| 分条带做底色 | 能把整屏/局部差从 32.5 压到 8.7，但引入 30+ 的左右梯度；条带先后顺序本身在决定颜色 |
| 黑保持/白保持当成同一个“00 无作用” | 没有支持；显式 L00 也没证明无作用 |
| 把 R20 逆变换直接套到整份 MTP | 只是可逆查看副本，不是解压；必须先解 LZ，再做字节逆映射 |
| 原厂 donor 快刷命令（E0/E6/A5 组合） | 有一次 DRF 120 s 不释放、POF 也超时，硬复位才恢复；不要重跑 |
| 把 R83 局刷当“零电场保持” | 窗口外仍可能变化；L00/source-disable/VCMZ 都不能无条件叫零场 |
| 拿 BUSY 时间证明画质 | BUSY 只说明扫描时长，不说明光学结果 |

## 4. 为什么视频没有打包

原仓库的视频路径是：

- 相机闭环 + 固定工位；
- 主机生成 2bpp 图、RLE/CRC、MCU 流水接收；
- 动态 LUT、三档调度、补驱动、错峰维护；
- 大量按内容/面积调出来的参数。

它确实跑过 384×288、24 fps 级别的 Bad Apple，但：

- 背景偏黄，黑端偏浅，运动有拖影；
- 条带做底会引入左右梯度，机理还没拆开；
- 不同内容/面积要不同参数，不是“设一个 30 fps 就完事”。

把这些代码原样放进分享包，会让人以为“这是可用播放器”，实际上是一个还没调完的实验台。所以本包只保留**结论和边界**，不保留视频引擎。要看实现，去原仓库的 `video_lab/`。

## 5. 测量口径

- **BUSY**：低电平持续时间。它能告诉你“扫了多少”，不能告诉你“看起来怎样”。
- **VSL/VSH/VCOM ADC**：测的是外部测试点/供电，不是芯片内部像素电极；分压网络没有独立校准。
- **相机 G 通道**：不是反射率。早期自动曝光/自动白平衡的图不能用于微小色差判断；后期固定曝光、手动白平衡、同次原厂白参照才有比较意义。
- **PLL 标称 50/100/120 Hz**：不是精密校准；实际帧周期会随温度/时钟漂移。
- **RAM 回读正确**：只证明数据写对了，不证明光学隔离或长期保持。

## 6. 如果继续研究

按优先级：

1. **先把“用”做好**：正常四彩全刷、R83 窗口、R93 回读。这些已经稳定，别再为了快而改初始化。
2. **再做“可控的波形”**：从已知工作的短表开始，一次只改一个字段；每次都用 R93 核对 RAM、用 BUSY 看时长、用相机看光学。不要一次改六个相位。
3. **MTP 整表复现**：先确认 535 B 表块在 SRAM 里的落点/头部/终止，再做 BUSY/VSL 对照，最后才谈光学。不要直接上传整份 11510 B。
4. **快速视频**：先把“面积效应/条带顺序”拆成单变量实验（同时打黑逐条擦 vs 逐条打黑同时擦），再谈调度。画质没解决之前，不要用“30 fps”命名。
5. **长期/寿命**：同一 PON、同一图像历史、固定曝光，至少几分钟到几小时；不要拿几十秒的结果外推。

## 7. 安全清单

- 逻辑 3.3 V；不要接 5 V 信号。
- 面板高压由原 PCB 的 boost 提供；不要用 Pico 3V3 直接供高压。
- 共地；断电后再插拔 FPC。
- 不要发 MTP 编程/擦除、OTP 写入、未知的 `A2`/donor 级联命令。
- PON/DRF/POF 都有 120 s 上限；失败时尽力 POF，再复位。
- 不要长时间停在高压/powered 状态；实验结束 POF。
- `readraw` 这类“读”可能真的写易失寄存器；不确定的命令不要扫。
- 面板发热、异味、BUSY 长期不释放：立刻断电，不要反复复位硬撑。
