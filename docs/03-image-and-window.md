# 03 · R83 窗口与镜像坐标

R83 把图像写入和刷新操作定位到一个矩形窗口，适合更新局部内容。它解决位置与范围，DRF 使用的波形决定时间：早期不同窗口尺寸的对照中，数据传输量随面积减少，原厂 DRF 仍约 15.2 秒。因此局部更新可以先减少传输，自定义短波形则用于进一步缩短刷新。

## 1. R83 的 9 个字节

```text
XSTART_H XSTART_L XEND_H XEND_L YSTART_H YSTART_L YEND_H YEND_L 01
```

- 坐标是**编码坐标**，不是可见坐标。
- 最后一个字节 `01` 是原厂全窗参数里的值；本包按已验证值发送，没有单独解释它的全部含义。
- 全窗：`00 00 03 1F 00 00 02 57 01`（x 0..799，y 0..599）。

## 2. 为什么 X 要镜像

这块屏在 SHL=0 时，R83 的 X 和实际 RAM 是反的：

```text
实际 RAM x = 800 - encoded_x - width
```

反过来：

```text
encoded_x = 800 - 实际 RAM x - width
```

可见坐标还要加 32：

```text
实际 RAM x = 可见 x + 32
encoded_x  = 800 - (可见 x + 32) - width
```

Y 不镜像：

```text
实际 RAM y = 可见 y
```

### 例子 1：中央 256×128

可见窗口 `x=256..511, y=212..339`，宽 256：

```text
physical_x = 256 + 32 = 288
encoded_x  = 800 - 288 - 256 = 256 = 0x0100
encoded_xe = 256 + 256 - 1 = 511 = 0x01FF
y          = 212 = 0x00D4
ye         = 339 = 0x0153
```

R83：

```text
01 00 01 FF 00 D4 01 53 01
```

### 例子 2：可见 x=64..319，y=192..319

```text
physical_x = 64 + 32 = 96
encoded_x  = 800 - 96 - 256 = 448 = 0x01C0
encoded_xe = 703 = 0x02BF
y          = 192 = 0x00C0
ye         = 319 = 0x013F
```

R83：

```text
01 C0 02 BF 00 C0 01 3F 01
```

第一个例子位于中央，第二个偏向左侧；分别代入同一换算公式，可以检查镜像和 32 像素边距是否处理正确。

## 3. 窗口数据怎么排

- 数据按行，行内按 2bpp 打包。
- 每行字节数 = `width / 4`。
- 总字节数 = `width * height / 4`。
- 行与行之间**没有** 200 B 的全帧 stride，窗口 payload 是紧排的。
- width 必须是 4 的倍数；否则一个字节会跨窗口边界，本包不处理。

例：256×128 窗口 = 64 B/行 × 128 行 = **8192 B**。

## 4. 驱动里的用法

`driver/src/epd.h` 提供：

```c
bool epd_partial_update(uint16_t x, uint16_t y, uint16_t w, uint16_t h,
                        const uint8_t *data, size_t length);
```

- `x/y` 是**可见坐标**；
- `w` 必须是 4 的倍数；
- `data` 是紧排的 `w*h/4` 字节；
- 内部依次做：R83 → `0x10` + 数据 → 再 R83 → `0x12` + 等 BUSY。

例：在可见 (256,212) 画一个 256×128 的黑块（黑码 `00`）：

```c
static uint8_t block[256 * 128 / 4];   /* 8192 B，全部 0x00 = 黑 */

epd_spi_init();
epd_init();
epd_power_on();
epd_partial_update(256, 212, 256, 128, block, sizeof(block));
epd_power_off();
```

注意：这仍然走**原厂全刷波形**，所以还是约 15 秒；它只验证窗口映射，不是快速局刷。

## 5. 坐标关系如何得到，光学上又意味着什么

为了确定 R83 的编码坐标，研究中给 16 个窗口写入不同标记，再用 R93 读回完整 120000 B 图像 RAM。比较标记在实际 RAM 中的位置，得到本章的 X 镜像公式；这把“写到哪里”变成了可逐字节核对的问题。

另一个问题是窗口之外是否保持原色。光学实验中曾出现窗外轻微变色和旧图浅斑，说明图像 RAM 地址正确后，还存在电极驱动或图像历史方面的影响。

后续用两个不相交窗口作对照：左上小块仅正向驱动一次，再在右下小块反复负向 24 次、正向 24 次；左上没有继续明显变黑，只小幅变浅。它排除了“窗外旧像素的正向路径被完整重复执行”这一较强解释，但不足以确定窗外电场为零。这个对照可用于区分地址错误、旧内容重放和小幅光学扰动。

## 6. 常见坑

1. **忘了镜像。** 窗口内容会左右错位，或者写到屏幕另一边。
2. **把可见 x 直接填进 R83。** 会再偏 32 像素。
3. **每行按 200 B 发。** 窗口 payload 是 `w/4` 字节一行，不是全帧 stride。
4. **只减少窗口面积。** 能减少数据量；原厂 DRF 的主要时长仍由 LUT 决定。
5. **只回读 RAM 就判断显示正确。** RAM 回读检查数据位置；窗口内外的光学变化还需另行观察。
