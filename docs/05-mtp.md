# 05 · MTP：从压缩字节到原厂状态表

MTP 是控制器保存出厂资料的非易失存储区。它保存的波形并非直接可读的 11 B 状态数组，而是一段压缩数据。本项目从 R92 读出的 4096 B 样本中识别了 LZ 流，解出两张状态表。

这给后续研究提供了两种材料：一是原厂怎样安排相位与重复的完整例子，二是可以与硬件测量互相核对的字节来源。先看解码路线，再看容器里的具体偏移。

## 1. 解码路线与可运行例子

```text
4096 B MTP 样本
  → 从 0x016 开始解 LSB-first LZ
  → 11510 B R20 wire 字节
  → 逐字节执行 R20 逆映射
  → 逻辑字节：两张 535 B 状态表 + 尚未解释的尾部
```

从仓库根目录运行：

```sh
python3 host/decode_mtp.py
python3 host/show_profile.py --lane 5
python3 host/decode_mtp.py --out /tmp/jd79665-decoded
```

第一条打印流长度、表头与六路扫描数，第二条展开 H5 的每个状态，第三条导出完整解压结果和两张表的 logical/wire 文件。保存的文件与 [data/](../data/README.md) 中的样本可以逐字节比较。

最初曾尝试直接对 MTP 每个字节应用 R20 逆映射，因为 R20 中有已知的取反与位重排。该变换虽然可逆，却没有处理压缩 token，所以无法恢复状态结构。识别 LZ 之后才明确：**压缩表示和 R20 字节编码是两层格式，先解压，再逆映射。**

## 2. LZ 流如何表示重复数据

每个字节内部先读低位，每个多 bit 整数也先读低位。token 有三种：

```text
0 + literal:8                   输出一个字节
1 + length_code:8 + distance:14  从已输出内容的 distance 字节前开始，
                                逐字节复制 length_code + 3 字节
length_code=255, distance=0     流结束
```

复制允许重叠。例如已有一个 `FF`，距离 1、长度 5 的回溯可以继续输出五个 `FF`，后面复制的字节来自刚刚生成的结果。两张状态表共享同一个历史缓冲区，实际出现过距离 535 的回溯；因此第二张表要从整段流的解压结果中截取。

已识别样本共 374 个 literal、159 个 reference、1 个 end，消耗 7046 bit，输出 11510 B。结束 token 消费完毕后的游标是 `0x386 bit6`，即该字节下一未读位；流最后一位为 bit5，余下两位是填充。

`host/mtp_lz.py` 检查截断、引用是否超出已有输出以及输出上限。样本里未出现 `length_code=255` 且距离非零的形式，当前解码器对这种组合报告未支持。

## 3. 识别出的两张表

535 B 的结构与 R20 状态模型一致：`7 + 6×8×11`，即七字节头部、六路、每路八个状态。

| 表 | 解压偏移 | 长度 | 逻辑头部 | 每路总扫描数 |
| --- | ---: | ---: | --- | ---: |
| profile 0 | 0 | 535 B | `00 3C 28 78 3E 00 08` | 1399 |
| profile 1 | 535 | 535 B | `00 22 24 78 22 00 08` | 742 |

profile 1 的六路，逐状态扫描数均为 `108, 64, 74, 140, 160, 155, 33, 8`。profile 0 的各路内部时长分配不同，但总数都为 1399；它提供了另一种完整时序，而非 profile 1 的简单倍长版本。

## 4. profile 1 和实测对上了什么

### 为什么先前就有一份独立参照

在解压 MTP 之前，已经通过修改 R20 前缀、比较 BUSY 与 VSL 供电跳变，逐项恢复过原厂长波形的时长字段。例如固定状态其他部分，分别让 G=2、G=3，使目标时长超过其他路径的下限，两次差值就给出多执行一次该状态的成本；再改变 A、RA 等字段，用差分斜率区分相位长度和重复数。

这个方法得到的是在测量条件下可以区分的字段。若 D/E/F 都为零，那么 RB 是 0 还是 1 都不增加扫描，时间测量无法唯一确定它。为保留这种差别，参照同时记录代表值、已辨识位掩码和候选位掩码。

### 随仓库提供的对照

[data/measured-reference.json](../data/measured-reference.json) 保存此前硬件测量的 535 B 逻辑代表值和两份位掩码。它由既有测量记录导出，没有从本次 MTP 解码结果补齐。掩码为零的位置表示该位没有由相应测量类别确定，代表值在这些位置只是占位。

比较方法为 `(mtp_byte XOR measured_value) AND mask`，统计其中为 1 的 bit。`python3 host/selftest.py` 自动执行这个对照：

| 项目 | 数量 | 对照结果 |
| --- | ---: | --- |
| 已辨识位：有差分或反例支持的测量字段 | 3194 bit | 0 bit 不一致 |
| 候选位：与测量相符，但尚未唯一确定 | 66 bit | 0 bit 不一致 |
| 六路各八状态、除两个 level 字节外的时长字段 | 432 B | 431 B 完全相同，1 B 属于等价差异 |

差异在 **H5 第 7 状态的 RB**，表块偏移 534：测量代表值为 0，MTP 为 1。这个状态 D=E=F=0，两种 RB 都不增加扫描。该差异说明文件来源能补足时间测量无法分辨的值。

本仓库提供的对照数据可复现字节与掩码的比较，完整的逐次电压采样与测量装置则没有作为工具依赖引入。

### 文件额外给出的信息

profile 1 的 H0–H4 首状态 G 都为 1；某些首状态计数此前会被较长的 H5 遮蔽，单看总 BUSY 无法区分它们。H0 八个状态的 ABC level 字节均为 `02`、DEF 为 `00`，六相位电平码都是 `00`；这个码在 VCOM 实测中与同轮原厂的约 2096 ADC 基准平台对应，因此表中持续选择基准档，与原厂 VCOM 近似直流的观察相符。具体码表与前后原厂对照见 [H0 电平与原厂 VCOM](04-lut.md#63-h0-电平码与原厂-vcom-的对应)。ABC 的低位 bit1 另外保留在完整字节中。H5 和像素各路的完整 level 字节也来自文件解码，低位含义仍可继续分析。

头部第七字节为 `08`，与 H1 首槽在非零头字节下出现部分计数恢复的实验相容；该头字段的完整功能还没有由这些观察唯一确定。

## 5. 原始容器与表选择问题

样本为 `data/mtp.bin`，4096 B，SHA256 为 `150470090f544d6f8da303ce0fbe8f085c129e7b325e44bca9157a191dcddda4`。读取使用 R92 专用流程：命令后先接收一个完整 dummy 字节，再读 4096 B；记录的 dummy 为 `0E`。同一控制器的 R70 返回 `0E 02 01`，属于另一个识别响应。

| MTP 偏移 | 已观察内容与当前解释 |
| --- | --- |
| `000–015` | 22 B 封装头，含 `0F` 与 15 个 `7F`；字段含义待分析 |
| `016–386` | 上述 LZ 流，最后一字节只有部分位属于流 |
| `387–47E` | 连续 FF |
| `47F` | 单独一个 77，容器作用待分析 |
| `480–EFF` | 连续 00 |
| `F00–F05` | `43 4A 31 54 4D 01`，包含 ASCII `CJ1TM` |
| `F06–F56` | 连续 00 |
| `F57–F84` | 46 B 存储设置区，首字节 A5；保存值与活动配置并不完全相同 |
| `F85–FFF` | 尚未解释的设置/标识区；其中 `FD0` 有 ASCII `NK863` |

表中偏移为十六进制。存储设置区中记录的几何为 800×480，而驱动正常运行时配置的是 800×600；这说明读取 MTP 设置区与读取当前活动寄存器是不同操作。

两张状态表一长一短，封装头又有重复结构，因此温区选表是一个合理的研究方向。目前尚未通过改变温度或跟踪装载行为确定选择规则，本文使用 profile 0/1 作为中性编号。

## 6. 从表块到实际执行配置

解压输出在两张表之后还有 52 B 尚未解释的数据（偏移 1070–1121），从 1122 起为逻辑零。11510 B 是容器解压长度，535 B 是识别出的表块长度，2048 B 是 R20 写地址周期；三者分别描述不同层次。

目前完成的是文件解码与独立实测字段对照。将整张表块放入 R20 运行空间后，仍需确定尾部终止、表选择和配套电压配置，再比较 BUSY、供电跳变与显示效果。这给下一步工作提供了明确的输入和待核对项目。
