# 06 · 快刷实验：思路、对照与结果

正常四色刷新约 15.2 秒。研究快刷的目标，是用更短的波形完成黑与浅色之间的切换，并让静止区、运动边缘和复杂历史后的画面保持可读。本章说明几条已尝试的路线，重点是每条路线试图解决什么、怎样验证，以及结果如何改变下一步判断。

前两节涉及控制器状态和刷新时序，适合移植驱动时参考；后面涉及像素的光学响应，适合设计自定义波形时参考。实验条件和数值放在各节内，阅读不需要原实验仓库。

## 术语与测量

`DRF` 是一次 `0x12` 刷新。`P` 表示 Mode0 下的 L01 正向驱动，`N` 表示 Mode0 下的 L10 负向驱动；`P3` 就是持续三个物理扫描。Mode0、Mode1 是 H5 控制的两种 source 供电配置，同一个电平码在不同模式下不一定得到相同电压。需要 Mode1 的地方会明确写出。

“获取”是像素刚换目标时连续几次同向驱动；“维护”是在目标不变时偶尔补一个脉冲；“清理”是额外插入一段较长波形，试图减少此前驱动留下的残留。它们描述动作，不依赖原播放器的命令名。

相机数字使用固定曝光与白平衡。`L` 是相机亮度代理量；明确采用平均 RGB 的实验使用 `L=(R+G+B)/3`。`R−B` 是红通道减蓝通道，在这些黄底实验里用来比较黄度。不同拍摄会话的曝光与白参考不同，数值只在各节所述对照中比较。

### 短波形的共同配置

第 3–9 节的短波形主线使用 PSR=`4B F9`、PLL=`07`（标称 120 Hz），供电寄存器 R01=`3F 00 14 00 50 14`；第 5 节的 VSP_1 对照会改变 R01 第四参数，第 6 节的长清理另行注明配置。图像与 LUT 传输使用更高的 SPI 请求频率，典型请求 16 MHz、实际 15.625 MHz。

短表由完整 2048 B 逻辑零底板构造，头部字节 6 设逻辑 1。H2 对应黑目标，H3 对应白/浅色目标，H5 安排供电模式；普通保持像素使用 H1 的终止路径。相位状态通常 G=1、RA=1，需执行 D 段时 RB=1，其余时长零。第 9 节的全局弱补白会明确重定义保持路径。

例如 P3/N3 的最简路径如下。其表内时长、字段打包和 wire 编码均可用 [第四章的工具](04-lut.md)构造：

| 路径 | A 相电平码 | A 相扫描数 | 后续 |
| --- | ---: | ---: | --- |
| H2 黑目标 | 01（L01） | 3 | 下一状态 G=0 |
| H3 浅色目标 | 10（L10） | 3 | 下一状态 G=0 |
| H5 供电模式 | 00（Mode0） | 3 | 下一状态 G=0 |

这个码表与原厂黑/白/黄/红码表用途不同，原厂图像不直接复用为这里的动作图。后续表格中的“扫描数”均指物理扫描；累计多次 DRF 时会明确说明次数。

## 1. 切回原厂模式为什么没有恢复原厂刷新

**问题与思路。** 修改自定义 LUT 后，需要一个原厂基线作对照。最直观的方法是把 PSR 从寄存器 LUT 切回原厂 LUT，再刷新一次；它隐含假设“模式选择会重新装载出厂表”。

**对照方法。** 正常初始化后，原厂条带刷新约 15.245 s。随后通过 R20 写完整 2048 B 的 `FF`，即逻辑零表，使寄存器模式刷新缩短到约 1.615 ms。保持其他配置不变，切回原厂模式并再次刷新；另测 POF/PON（关闭再开启高压）与复位初始化的区别。还用一个非空、含两段供电模式切换的 H5 标记，排除“只有空表才碰巧走快速退出”的解释。

| 同组内操作 | BUSY 低电平结果 |
| --- | --- |
| 原厂参考 → R20 空表，寄存器模式 | 15.245 s → 1.615 ms |
| 上述空表后切回原厂模式，刷新 | 1.614 ms，仍是空表行为 |
| 另一组空表 → 切原厂模式 → POF/PON | 6.475 → 6.468 ms，未恢复长波形 |
| 非空标记：寄存器 → 原厂 → 寄存器模式 | 357.900 / 358.096 / 358.193 ms |
| 复位 + 正常初始化 + PON，再选寄存器模式且不写 R20 | 15.232 s，恢复原厂时序 |

两组空表的绝对毫秒数不同，原厂刷新前后的动态时钟状态可能参与其中；判断依据是各组内部切换前后是否改变。

**得到的认识。** 原厂装载路径与 R20 可修改的运行内容存在关联。选择原厂模式、执行一次原厂模式 DRF、POF/PON，都没有在这些条件下重新装载原厂长波形。做候选波形的 A/B 对照时，已验证的原厂准备过程是复位、正常初始化、PON。恢复具体由组合中的哪一步触发，以及两种模式是否使用物理同址 SRAM，仍可进一步拆分。

## 2. 能否保留原厂波形，只提高时钟或选择快刷模式

**思路。** 在自己重写波形前，先尝试加快原厂时序，或借用同控制器其他屏幕的快刷选择过程。这样有机会保留原厂的颜色控制，只改变执行速度。

**固定 PLL 的结果。** 同一面板的原厂波形，在标称 50 / 65 / 75 / 85 / 100 / 120 Hz 下，DRF 分别约为 15.220 / 11.672 / 10.042 / 8.908 / 7.547 / 6.380 s。时间随扫描时钟缩短，但仍是秒级；主观观察还出现 85 Hz 偏黄、100 Hz 偏灰，画质并不随频率单调变化。它提供了一种秒级提速方式，未得到视频级刷新。

**借用其他屏幕命令的结果。** 另一条线索来自 GDEY1085F51 的同控制器方案。两次试验保留本屏正常初始化、完整 120000 B 四色图和原来的 DRF，只插入下面的命令：

| 插入时机 | 命令/参数（hex） | 观察 |
| --- | --- | --- |
| PON 之前 | `E0 02`、`E6 5A`、`A5 00` | 原厂 15.206 s → 15.202 s，未见明显加速 |
| PON 完成之后 | `E0 03`、`E6 5C`、`A5 00` | DRF 到 120 s 截止时 BUSY 仍低，随后 POF 也未完成；硬复位后恢复，人工观察画面未变 |

后续核对参考方案发现，它采用两个控制器级联，每片负责 680×480，E0 涉及级联同步配置。因此它与本屏单控制器配置存在结构差异。第二次的结果是未完成刷新，不能记录成“120 秒波形”；具体由哪个参数导致等待尚未隔离。可复用的线索是：借用同型号控制器的命令时，连同级联方式、面板几何和装载流程一起比较，比把三字节组合当成通用快刷开关更有依据。

## 3. 偏黄是黑色停留太久，还是反复驱动造成的

**起点。** 播放过程中，黑块翻成白色后容易残留黄色。最初看起来像“黑得越久，越难擦回白”，于是有两种解释：黑态静置随时间变化，或者黑区反复获取/维护，累计了更多驱动。

**把时间与脉冲分开。** 256×128 窗口先用原厂波形恢复白色，再把左半变黑并静置 10 秒，期间关闭该区域的像素维护。接着把右半刚变黑，两半一起用相同的四次获取过程翻白。固定曝光相机得到：

| 翻白前的黑历史 | 翻白后亮度 | R−B |
| --- | ---: | ---: |
| 刚刚变黑 | 142.4 | 20.2 |
| 黑态停留 10 秒、期间零像素驱动 | 145.1 | 20.1 |

两半黄度几乎相同。它修正了早期的时间解释：在这组对照中，黑态驻留本身没有产生额外黄度。后续应分别记录驱动次数、维护量和静置时间，而不是只记录“黑了多久”。

**继续区分黑剂量。** 另一组七条带用不同 P 剂量变黑，再统一用 36 个 N 扫描擦浅。黑态亮度在 18 个正扫描以后接近饱和，但擦浅后的黄度继续增加：

| 正向黑剂量（扫描） | 黑态 L | 统一擦浅后 R−B |
| ---: | ---: | ---: |
| 6 | 18.9 | 70.7 |
| 12 | 13.9 | 78.7 |
| 18 | 11.7 | 85.7 |
| 24 | 10.7 | 93.8 |
| 30 | 10.4 | 101.1 |
| 36 | 11.5 | 103.1 |

这组结果说明，可见黑度已经接近饱和时，继续同向驱动仍可能改变后续擦浅效果。把像素只建模成一个线性的“累计剂量→当前亮度”数值，会漏掉这部分历史。

## 4. 擦不干净，是否只要增加负向剂量

**假设。** 如果残留只是反向驱动不足，保持起始历史相同、逐步增加 N 扫描数，应该越来越接近未变黑的浅色参照。

**对照。** 原厂全刷两次后建立底色，七条带中六条经历相同变黑过程，再分别施加 12–42 个 N 扫描；最后一条保持为未经历黑态的参照。测量都来自同一画面。

| 负向擦浅剂量（扫描） | R−B | L |
| ---: | ---: | ---: |
| 12 | 58.3 | 120.6 |
| 18 | 79.3 | 117.7 |
| 24 | 87.4 | 117.2 |
| 30 | 93.0 | 117.4 |
| 36 | 92.5 | 118.6 |
| 42 | 80.7 | 122.4 |
| 未变黑参照 | 47.5 | 130.7 |

**结果与意义。** 黄度先增加再下降，所有剂量仍比参照更黄、更暗。这否定的是“在这条路径上只要继续加同向剂量，就会单调回到同一浅端”的假设。它没有排除其他电压、相位组合或初始准备方式，也没有从颜色数值直接识别出是哪种粒子的运动。

## 5. 正负组合能否用更少扫描得到白色

**思路。** 单向擦浅不够，于是在白目标的负向段之前加入正向预脉冲，尝试先改变内部状态，再把白色拉出来。同时希望把原先“黑三扫描 + 白六扫描”的九扫描过程缩短。

**波形定义。** 本组使用 256×128 窗口和标称 120 Hz。黑目标在 Mode0 接 L01；白目标可先在 Mode0 接 L01，再在 Mode1 接 L10。黑目标在 Mode1 段接 L00。每个条件先原厂刷白，再经过四次有限获取后测量，避免用单次驱动的浅黑误判配方。下表的扫描数是一次 DRF 的长度；相机比较的是这个相同获取流程之后的画面。

| 白目标的驱动；黑目标均先正向 3 扫描 | 每次 DRF 扫描数 | 白亮度 | 白 R−B | 实测/估计帧率 |
| --- | ---: | ---: | ---: | --- |
| Mode0 负向 3，与黑目标并行 | 3 | 136.9 | 18.2 | 实测约 26.5 fps |
| 正向 3 → Mode1 负向 2 | 5 | 117.3 | −10.5 | 估计约 18 fps |
| 正向 3 → Mode1 负向 3 | 6 | 130.9 | 0.0 | 实测约 15.7 fps |
| 正向 3 → Mode1 负向 4 | 7 | 135.0 | −0.4 | 估计约 13.5 fps |
| 正向 3 → Mode1 负向 6 | 9 | 139.0 | −0.7 | 实测约 11.2 fps |
| L00 等待 3 → Mode1 负向 6，无正预脉冲 | 9 | 144.5 | 0.8 | 实测约 11.2 fps |

**结果与取舍。** 正预脉冲能在六扫描时让 R−B 接近零，但白色同时变暗。把“黄度接近零”单独当作成功，会选出灰白配方。九扫描、不加正预脉冲的基线更亮，而帧率更低。这里得到的是已测波形中的取舍，没有证明所有短波形都无法兼顾亮度与色彩。

还试过让黑白都在 Mode1 中驱动，以省掉两段串行时间。将该模式的正压参数 VSP_1 从 `00` 调到 `2D`、`3F`，八扫描时黑目标亮度仍约 135.6、95.6；同组 Mode0 四扫描参考已经达到 44.2。这个设置范围内，Mode1 的黑化效率不足以抵消省掉串行段的收益。

## 6. 能否把长清理拆散到视频里

**思路。** 短波形负责帧率，偶尔用长正负组合恢复白色；如果整次清理太明显，就减少单次剂量并提高频率。这个想法希望把“恢复画质的成本”摊到播放过程中。

**实际尝试。** 256×128 窗口中，长清理采用 PLL=`02`（标称 50 Hz）、R01=`3F 00 14 00 24 14`：Mode0 正向 8 扫描后接 Mode1 负向 32 扫描，白处理约 821 ms；随后正向 8 扫描重建黑目标约 165 ms。人工观察黄度明显减轻。这表明长组合与短同向补驱动的作用不同，但同时带来约一秒的可见画面变化。

把这段过程每 300 张源帧执行一次，主机提交平均约 24.6 fps，仍能看到整次清理。另一组恢复 PLL=`07`、R01 的 VSN 参数=`50`，改为每 8 张源帧对白目标补 6 个 Mode1 负扫描、黑目标补 2 个正扫描，提交约 22.6 fps；人工观察仍偏黄，且能看到维护并伴随掉帧。这些是人工视觉结果，不是同一相机标定下的量化排名。

**可复用的认识。** “平均每帧多一个扫描”没有描述清理发生在哪些像素、以何种顺序发生，也没有描述画面是否闪动。长波形有效，并不意味着拆成低频单向脉冲还能保留同样作用；评估时需要同时记录恢复效果、瞬时画面变化和端到端节拍。

## 7. 全局做底与局部更新，为何颜色对不上

**问题。** 一开始给整个测试窗口做黄色底，再让中间的小块变黑、擦浅，会出现“更新过的地方比背景更浅”。如果底色与更新都用了相同正负扫描数，直觉上它们应回到同一个状态。

**同次对照。** 384×288 测试窗口先整窗正向 12 扫描、负向 24 扫描做底，再对中间小块执行相同组合。背景 R−B=135.7、L=97.1，小块 R−B=103.2、L=104.6，相差 32.5 和 7.5。停止像素驱动观察 60 秒后，两区黄度约为 135.1 和 103.4，差异并未随静置消失。

**下一步思路。** 把底色也拆成小面积更新：分六条带，逐条正向 12、负向 24 扫描。同次测量得到背景 R−B=54.4、L=128.6，更新块 R−B=45.7、L=126.5，差异缩小到 8.7 和 2.1。这说明更新面积或调度方式会影响最终状态。

**新的问题。** 等黑态停留时间的另一种条带调度产生左上/右上黄度 47.6/14.6、左下/右下 42.0/11.2，左右差超过 30；前一种条带顺序的色差方向又相反。因此分条带改善局部匹配的同时，引入了顺序相关的底色梯度。

驱动面积、黑态准备与擦除时刻在这些流程中会同时变化。供电压降或限流是一种解释，但本组没有同步电压测量，尚不足以单独归因。进一步拆分可以比较“所有条带同时变黑，再逐条擦浅”和“逐条变黑，再同时擦浅”。这比只调总扫描数更能识别影响来自哪里。

## 8. 多种历史能否收敛到同一个浅色

**思路。** 如果找到一条短周期波形，能把原厂白、黑、黑后擦浅、反复正负驱动这四种初态都拉到同一浅色，就有机会减少运动残影，而不必保存复杂像素历史。

**对照。** 在 384×288 窗口内用四行放四种历史、六列放不同候选，并倒置历史行序复测，以区分照明梯度。这里每个 P 或 N 都是含三个扫描的一次 DRF。相机以同次原厂白逐格校正，下面报告四种历史的极差：

| 重复的驱动周期 | 有功 DRF 数 | ΔL | Δ(R−B) |
| --- | ---: | ---: | ---: |
| 纯 N | 128 | 48.4 | 138.6 |
| P→N→N→N | 128 | 4.9 | 21.9 |
| P→N | 128 | 2.4 | 26.2 |
| 纯 P，作为深端对照 | 128 | 2.6 | 4.2 |

正负周期确实比纯负向更容易缩小历史差异，但收敛需要很多次驱动，而且相似亮度仍可能有不同颜色。P→N→N→N 在 24 DRF/s 下每个周期仅 6 Hz；周期内部一次 P 可让参照格 L 从约 140 降到 67，之后 N 回到约 136。因此周期末颜色接近，也可能伴随强烈的周期内闪烁。

把正负段合到同一次 DRF（P1 扫描 → N2 扫描）后，128 次的 ΔL=4.2、Δ(R−B)=9.3，但 8 次时 ΔL 仍约 47。这个组合改善了最终收敛，却没有实现几次刷新内消除历史。

另外，四种初态先统一打黑四次后，可见 L 已接近 `9.0 / 6.3 / 10.2 / 15.2`；再统一负向四次，变成 `144.3 / 147.9 / 136.1 / 113.3`。可见黑态掩盖了部分差异，后续擦浅仍会显露。这解释了为什么“先都打成一样黑”未必构成足够强的复位参考态。

## 9. 全画布持续弱补白，能否压住残影

**思路。** 接受黄色背景后，尝试每次刷新都给所有像素一个很短的反向脉冲，让浅色持续受到维护；黑目标再补正向脉冲。这里“弱”只指持续一个扫描，电压档没有单独降低。

**实际波形。** 每个 DRF 先给全窗口 Mode0 N1。黑目标随后 P2；变浅和保持像素都只有 N1。黑目标刚出现时连续获取两次，然后比较“每次都补 P2”和“隔一次补 P2”。因此这组比较同时改变了黑端的持续维护量。

| 黑目标维护 | 静止黑块 L | 运动第 16 帧旧位置 L 减背景 L |
| --- | ---: | ---: |
| 每次补 P2 | 22.4 | −60.4 |
| 隔次补 P2 | 36.2 | −45.0 |

两组各发送 1024 张地图，约 23.316 DRF/s。隔次补黑后旧位置与背景的亮度差缩小，但黑块也明显变浅，仍有暗黄拖影；人工观察还见到黑色闪动。减少残影数值的同时损失了对比度，不能仅凭旧位置差变小选用这条路线。

后续回到直接 P3/N3、变色后四次有限获取，再给静态黑像素每八张源帧补一次 P1，按行错峰。人工反馈黑端改善、泛白变成较弱波纹；这项改善是视觉反馈，尚没有同组相机量化。它提示维护可以按黑端、浅端分别设计，不必要求两者对称。

## 怎样利用这些结果继续工作

这些试验分别暴露了几个独立变量：运行 LUT 是否恢复、扫描时钟、像素历史、驱动极性与持续时间、活动面积、维护时刻。要对比新的波形，可以先固定其他变量，用原厂显示作同次参考，再分别检查数据位置、BUSY 时序和最终画面。

R20 的字节与状态格式见 [第四章](04-lut.md)。MTP 解出的两张表为长波形分析提供了可读样本，见 [第五章](05-mtp.md)。本章给出的是实验方法与结果，波形中的相位可以按这些定义重新构造；播放器、相机采集程序和完整视频日志未作为运行依赖引入本仓库。
