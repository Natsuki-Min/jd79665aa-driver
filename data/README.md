# MTP 样本、状态表与实测参照

这里提供一份 SE0398NZ07A1 的 4096 B MTP 样本，以及从中提取的两张波形表。它们用于学习文件格式、分析原厂时序和验证解码器。另附一份在解压前就已获得的硬件测量参照，用于交叉检查 profile 1。

## 文件各自表示什么

| 文件 | 大小 | 内容 |
| --- | ---: | --- |
| `mtp.bin` | 4096 B | R92 读出的原始 MTP 内容 |
| `profile-00.logical.bin` | 535 B | 第一张逻辑状态表，六路各 1399 扫描 |
| `profile-00.r20.wire.bin` | 535 B | 第一张表的 R20 编码字节 |
| `profile-01.logical.bin` | 535 B | 第二张逻辑状态表，六路各 742 扫描 |
| `profile-01.r20.wire.bin` | 535 B | 第二张表的 R20 编码字节 |
| `measured-reference.json` | 文本 JSON | 此前硬件测量的逻辑代表值、已辨识位与候选位掩码 |
| `SHA256SUMS` | 文本 | 上述六个文件的完整性校验值 |

一张表为七字节头部加六路、每路八个 11 B 状态。logical 文件适合直接查看字段；wire 文件已经完成 R20 的位重排与取反，适合研究传输编码。表块长度为 535 B，完整解压输出还包含其他数据；它们与 R20 的 2048 B 写地址周期的关系见 [MTP 章节](../docs/05-mtp.md)。

profile 0/1 是文件中的顺序编号。两张表可能与温区或其他选择配置有关，具体规则尚未通过装载行为确定。原样本也保留了设置区和标识字符串，方便从容器整体继续分析。

## 实测参照怎样使用

`measured-reference.json` 的三个十六进制字符串各解出 535 B：

- `values_logical_hex`：测量流程保存的一组逻辑代表值；
- `inferred_mask_hex`：3194 个已辨识位，有差分或反例支持；
- `candidate_mask_hex`：66 个匹配候选位，尚未唯一确定。

每个掩码字节中为 1 的 bit 表示纳入该类比较。掩码为零的位置不表达“已测得零”；例如像素电平中的许多位没有独立测量，代表值在那里只是占位。比较式是 `(profile_byte ^ reference_byte) & mask`。

profile 1 在两类掩码下都没有不一致位。432 个时长代表字节中有一处 RB=0/1 的等价差异，原因和原厂字段恢复方法见 [实测对照](../docs/05-mtp.md#4-profile-1-和实测对上了什么)。自检会重新计算这些数字。

## 复现与核验

从仓库根目录运行：

```sh
python3 host/selftest.py
python3 host/decode_mtp.py --out /tmp/jd79665-decoded
(cd data && sha256sum -c SHA256SUMS)
```

样本提供了字节层面的格式实例；完整表块如何装载、选择和配套电压配置，属于下一步的执行验证工作。
